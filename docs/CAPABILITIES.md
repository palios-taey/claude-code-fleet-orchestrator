# Live Capability Ledger

This page is a claims ledger for the current `claude-code-fleet-orchestrator`
main branch. Each row states whether the capability is live by default,
flag-gated, or delegated to `claude-code-fleet-notify`, and gives a direct way
to observe the behavior.

| Capability | Current status | How to observe it |
|---|---|---|
| Tasks | Live by default. `OrchTask` nodes are served by the FastAPI task routes; terminal writes require evidence. Completed writes first pass a shape/plausibility filter, then surface `completion_evidence_verification`: `VERIFIED` only when GitHub confirms the commit exists in the explicit `evidence.repo`, that repo is present in `ORCH_COMPLETION_ALLOWED_REPOS`, and the repo's verification profile passed; or when non-production research/prototype evidence includes `supervisor_verification` with `mode`, distinct `verifier`, and `observation`. Gated repos require their configured independent gate contexts for the exact `commit_sha` from trusted GitHub actors/apps; repos without an override use the global default gate list. Gateless repos require the commit to be reachable from the repo default branch. Commit evidence without `repo` is rejected instead of guessing a fallback repo, and `supervisor_verification` never bypasses commit-backed GitHub verification. For no-`commit_sha` completions without valid supervisor verification, the configured runtime repo classifies the task first, and `evidence.repo` is only context when no runtime repo is set; if the selected repo is allowlisted as `:gated`, completed writes without `commit_sha` are rejected so observation-only evidence cannot bypass open-PR and required-gate checks. Gateless/local/non-repo completions without `commit_sha` stay completed but explicitly unverified, and off-allowlist commit repos stay `UNVERIFIED`. Evidence containing `loop_proof` uses the careers loop-proof verifier instead: the receipt command strings are treated as untrusted templates and re-run through fixed read-only verifier implementations, with unknown commands failing closed. Tasks whose markdown metadata sets `[delivery_gate: true]` require exactly one delivery outcome in completion evidence: a non-empty `delivered` object or a checked `no_op` object with `reason` of at least 8 characters and `checked:true`. | `taey-task --help`; `GET /api/tasks/ranked`; `GET /api/tasks/{id}`; `PATCH /api/task/{id}` with `{"status":"completed","evidence":...}`. |
| Plans | Live by default. Markdown plans ingest to Neo4j projects, phases, tasks, dependencies, owners, priorities, refs, and user stop conditions. | `taey-plan ingest <plan.md>`; `docs/PLAN_FORMAT.md`; `GET /api/projects/{id}`. |
| Stop engine | Live by default. Session stop decisions are computed from active supervised projects, ready work, structured intentional waits, peer liveness, and user stop conditions. Only exact `AWAIT:<kind>:<detail>` markers (`human-review`, `family-consent`, or `external-signal`) create machine-resolvable intentional waits that exempt worker-liveness; free-text `blocked_on` is informational only and can be liveness-expired back to pending with teaching. Worker liveness refreshes from a matching `current_task` plus fresh `last_tool_activity` or age-bounded `tool_running_at`/session activity; stale `tool_running` alone does not protect work, and a live outward-action `effect_class` guard prevents clearing the executor's `current_task` mid-action. `orch-watch` also reconciles proven stale tracker tasks: worker `last_outcome=error/interrupted` for the matching `current_task` becomes terminal `failed/interrupted`, and explicit PR-linked tasks auto-close only when `dispatched_pr_*` or `produced_pr_*` task fields identify a merged PR whose required completion gates verify for the PR commit. PR numbers in descriptions are treated as context only and cannot complete a task. Cross-session cascades should use `AWAIT:external-signal:<id>` and clear it when the external executor lands. | `GET /api/sessions/{session}/stop-decision`; `fleet_orchestrator/orch_schema.py:get_session_stop_decision`; `fleet_orchestrator/task_reconciliation.py:reconcile_stale_tasks`; `fleet_orchestrator/worker_liveness.py:escalate_stale_worker_tasks`; `tests/stale_task_reconciliation_acceptance.py`; `tests/worker_task_liveness_acceptance.py`; ship-gate stop acceptance tests. |
| Session pause | Live API state. `POST /api/sessions/{session}/pause` makes that session's stop decision `ALLOW_STOP`; a `pause_expires_at` value creates a timed Redis pause that expires, while omitting it creates an indefinite pause until `DELETE /api/sessions/{session}/pause`. | `POST /api/sessions/{session}/pause`; `DELETE /api/sessions/{session}/pause`; `tests/session_pause_acceptance.py`. |
| Dispatch | Live by default. Dispatch refuses a target whose CLI hook settings do not contain the managed notify hooks, then claims a task, writes Redis `current_task`, assembles the worker's wake packet, embeds the dispatch body in that packet, sends the rendered packet through `taey-notify`, and rolls back the claim if packet rendering or wake delivery fails. Direct `dispatch()` to a hooked target receives global/supervisor/project rules and context; `ORCH_WAKE_PACKET_ENDPOINT_ENABLED=0` disables only the side endpoint, not dispatch injection. Task-bound dispatch packets include a first-action `loaded refs: ...` injection receipt for the rendered task refs, and the expected line is included in dispatch metadata/decision receipts. If full task-scoped context selection is unavailable for an ad-hoc/no-Neo4j dispatch, dispatch still sends a packet built from dispatch-local state plus available rules and includes a visible warning instead of sending an un-injected prompt. A dispatcher cannot silently overwrite a different dispatcher's live graph-backed `current_task`; it gets `worker busy with <dispatcher>:<task> (status)` unless it explicitly uses `force=True` / `taey-task dispatch --force`. A graph-backed binding whose task has moved out of `in_progress`/`dispatched` is stale and is cleared/replaced during dispatch; inspected stale session state can also be cleared with `DELETE /api/sessions/{session}/current-task` or `taey-task unbind <session>`. | `fleet_orchestrator.dispatch.dispatch(...)`; `fleet_orchestrator.hook_installation.hook_installation_status(...)`; `taey-task dispatch --help`; `taey-task unbind --help`; Redis key `${NOTIFY_KEY_PREFIX:-taey}:<worker>:current_task`; `tests/hook_installation_acceptance.py`; `tests/dispatch_mandatory_injection_acceptance.py`; `tests/dispatch_wake_atomic_acceptance.py`; `tests/dispatch_clobber_guard_acceptance.py`; `tests/injection_receipt_acceptance.py`. |
| Recurring cadence | Live by default. `orch-cron` `task_id` triggers cadence-dispatch a specific re-claimable recurring task. `project` triggers accept `mode:"advance"` or `mode:"reset"`; omitted mode defaults to `advance`. `advance` dispatches the project's current next-ready task without resetting any task state, then re-claims the completed recurring step with the lowest reclaim count after the dependency chain drains. `reset` resets the whole project to pending before selecting next-ready, so each scheduled fire starts at the chain entry. | `orch-cron --registry <json>`; `docs/PLAN_FORMAT.md`; `tests/recurring_task_cadence_acceptance.py`; `tests/orch_cron_project_trigger_acceptance.py`. |
| Chat | Live by default. The API mounts chat routes unless `ORCH_CHAT_ENABLED=0`; chat stores per-lineage history in Redis and should be exposed only on loopback or a trusted/token-protected LAN. | Dashboard chat bar; `fleet_orchestrator/chat_layer.py`; `tests/decision_receipt_acceptance.py` chat receipt checks. |
| Refs | Live but fail-safe gated by allowed roots from `ORCH_REF_ALLOWED_ROOT` plus repo roots auto-derived from `ORCH_SESSION_ROOTS`. Plan refs are stored as structured metadata and rendered as file-line pointers when allowed. | Add `[ref: path]` or `[ref: path:Lx-Ly]` to a plan, configure `ORCH_REF_ALLOWED_ROOT` or `ORCH_SESSION_ROOTS`, then inspect `GET /api/projects/{id}` ref_context. |
| Wake packet | Live by default. `ORCH_WAKE_PACKET_ENDPOINT_ENABLED=0` disables only the provenance-bound packet endpoint; deprecated alias `ORCH_WAKE_PACKET_ENABLED` is still honored. Dispatch still assembles and sends the packet mandatorily before notify. The assembler renders Operating, per-role Identity, refs, memory, rules, and state; empty ref tiers mean no refs were attached or selected for that tier. Task-bound packets include a first-action `loaded refs: ...` line derived from the rendered task refs, and the endpoint returns the same expectation in `packet_meta.injection_receipt`. Managed notify hooks fetch this packet on `SessionStart` and `UserPromptSubmit`, and append it on `PostToolUse` after drained notifications. | `GET /api/sessions/{session}/wake-packet?cli=claude`; `fleet_orchestrator.dispatch.dispatch(...)`; `docs/DYNAMIC_CONTEXT_REFS.md`; `tests/wake_packet_acceptance.py`; `tests/injection_receipt_acceptance.py`; `tests/dispatch_mandatory_injection_acceptance.py`; notify hook scripts named session_start.py, prompt_activity.py, and check_notifications.py; packet fields `packet_id`, `provenance_hash`, `snapshot.identity`, and `packet_meta.injection_receipt`. |
| Memory tier | Live by default when local memory files exist. The wake-packet Memory section loads operator-authored markdown from `global.md`, supervisor files, and project files under the configured memory root (`ORCH_MEMORY_ROOT` or the repo `memory/` directory). Entries are ranked project, supervisor, global, capped before rendering, and rendered as untrusted data. With no matching memory files, the packet says `none selected`. | Set `ORCH_MEMORY_ROOT` to an override memory directory and observe `tests/wake_packet_acceptance.py`; call `fleet_orchestrator.memory_tier.get_memory(...)`; inspect `## Memory`; `memory/README.md`. |
| Rules tier | Live by default. The wake-packet Rules section loads `rules/global.md` for every session, then local operator overlays from `rules/supervisors/{session}.md` and `rules/projects/{project}.md` or an override `ORCH_RULES_ROOT`. If an override store is not bootstrapped with `global.md`, the packet renders a distinct repair line instead of silently saying `none selected`. | Set `ORCH_RULES_ROOT` to an override rules directory and observe `tests/wake_packet_acceptance.py`; `GET /api/sessions/{session}/wake-packet?cli=codex` and inspect `## Rules`; `rules/README.md`; `rules/global.md`. |
| Decision receipts | Live by default. `ORCH_DECISION_RECEIPTS_ENABLED=0` disables best-effort content-hashed receipt writes to Redis stream `orch:streams:decision_receipts`; `taey-receipts` reads the same stream for operator explainability. | `taey-receipts list --limit 5`; `taey-receipts list --json`; `tests/decision_receipt_acceptance.py`. |
| Lane usage measurement + routing policy | Measurement is live on demand. `taey-lane-usage` reads native Claude Code/Gemini/Grok/Codex local token/rate-limit logs into normalized `LaneUsage` records and appends them to `lane_state:calibration` only when run with `--record`. `fleet_orchestrator.router` is an advisory policy sibling to dispatch: it consumes lane-state estimates and caller-supplied lane profiles to return a worker id plus receipt, but it does not claim tasks, write `current_task`, or send wake packets. Sacred Trust / Liberty Trinity work is no-route pinned to a high-fidelity lane and fails closed when none is viable; reserved lanes are hard-excluded unless the task explicitly matches the reservation. | `taey-lane-usage --help`; `fleet_orchestrator/cli_usage.py`; `fleet_orchestrator/router.py`; `tests/cli_usage_adapters_acceptance.py`; `tests/lane_state_acceptance.py`; `tests/router_policy_acceptance.py`; Redis key `${NOTIFY_KEY_PREFIX:-taey}:lane_state:calibration` or the `--prefix` equivalent. |
| Gate template | Live by default for plans that request it. `ORCH_GATE_TEMPLATE_ENABLED=0` disables applying the scout/code/audit/review/approval gate scaffold during plan ingest; `ORCH_GATE_OWNERS` can map those stages to local sessions. | `fleet_orchestrator/orch_template.py`; `tests/orch_template_acceptance.py`; ingest a plan with `[template: forced-subrole-gate]` and inspect created gate tasks. |
| Loop engine | Live by default. `ORCH_LOOPS_ENABLED=0` cleanly disables the additive loop declaration/advance/should-stop APIs with `ok:false`, `enabled:false`, and `reason:"loops disabled"`; no `orch-loop` CLI or core dispatch integration is shipped on main. | `POST /api/loops/declare`; `POST /api/loops/{loop_id}/advance`; `GET /api/loops/{loop_id}/should-stop`; `tests/loop_engine_acceptance.py`. |
| Notify | Delegated to `claude-code-fleet-notify`. Dispatch honors `ORCH_NOTIFY_CLI` through `OrchConfig().notify_cli_path`; the session notify API and loop wake routing invoke `taey-notify` on `PATH` in current main. | `ORCH_NOTIFY_CLI`; `fleet_orchestrator.dispatch.dispatch(...)`; `POST /api/sessions/{target}/notify`; `fleet_orchestrator.loop_engine.send_loop_wake`; notify repo README. |
| Daemon | Delegated to `claude-code-fleet-notify`. The notify daemon injects Redis inbox pointers into idle tmux sessions; orchestrator `scripts/install` may start that delegated daemon when notify is available. | `scripts/install`; `claude-code-fleet-notify/scripts/start_notify_daemons.sh status`; orchestrator `scripts/install` can wire notify when available. |
| Notify watchdog | Live by default in `orch-watch`, guarded by `ORCH_NOTIFY_DAEMON_WATCHDOG`. It checks the delegated notify router systemd service, `taey:_notify_daemon:heartbeat` freshness, and old `${NOTIFY_KEY_PREFIX:-taey}:*:inbox` messages. Service or heartbeat liveness failures alert out-of-band through direct tmux submission plus critical log/desktop notices. Stuck-inbox delivery SLO incidents first reconcile usage-limit idle state and then alert the configured watchdog inbox once per stuck message if still unresolved. | `orch-watch --help`; `fleet_orchestrator/cli_orch_watch.py:check_notify_daemon_liveness`; `fleet_orchestrator/cli_orch_watch.py:check_stuck_inbox_delivery`; `tests/notify_daemon_watchdog_acceptance.py`; Redis key `taey:_notify_daemon:heartbeat`. |
| Handoff | Split. Orchestrator stores dispatch/task state; explicit handoff records and passive receipts live in `claude-code-fleet-notify`. | Orchestrator: `fleet_orchestrator.dispatch.record_outcome(...)`; notify: `taey-handoff`, `notifications/handoff.py`. |
| Trace | Split. Orchestrator emits default-on decision receipts readable with `taey-receipts`; notification delivery trace lives in notify Redis stream `taey:notify_trace`. | Orchestrator: `taey-receipts list`; notify: `taey-trace` and `notifications/trace.py`. |

Documentation rule: if a row cannot be observed by the command/file named in
the right column, treat it as a bug in either the docs or the implementation.
