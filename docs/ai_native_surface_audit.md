# AI-Native Surface Audit

Status: audit ledger reconciled with remediation status. Fixed rows cite the PR that made the surface self-teaching.

Principle under test: an AI with no surrounding chat context should be able to read the emitted error, rejection, wake state, or CLI output and know what it has, why it is blocked or ready, and what to do next. A surface is a gap when it assumes prior context, points away from the product instead of teaching in band, or rejects a legitimate participant from its own work. The participant rule is the PR #163 rule: a session can be barred from supervisor-only capabilities, but it must not be rejected from its own current or next-ready work.

Scope inspected:

- `fleet_orchestrator/orch_schema.py`: domain errors, evidence gates, stop/wake decisions, pause/project/question validators.
- `fleet_orchestrator/tasks_api.py`: HTTPException details and JSON error bodies.
- `fleet_orchestrator/cli_taey_plan.py`: `taey-plan` command output and failure output.
- `fleet_orchestrator/cli_taey_task.py`: `taey-task` command output and failure output.
- `fleet_orchestrator/context_assembler.py` and `fleet_orchestrator/dispatch.py`: wake-packet Operating states, dispatch prompt, completion wake.

Summary:

- Rows audited: 84.
- Gap rows: 34.
- Strongest surfaces: stop-decision reasons, wake-packet Operating section, source/ref-root registration errors, evidence-gated completion guard, peer self-completion rejection.
- Main gap pattern: terse generic validation or raw exception passthrough tells an agent what failed, but not the exact next command/body/header to use.

## Triage Notes

Priority should favor surfaces that occur during autonomous stop/dispatch loops:

1. Highest leverage: CLI/API generic error wrappers (`CLI-01`, `CLI-11`, `API-04`, `API-06`) because they hide otherwise good backend detail from the agent actually operating the system.
2. Stop/wake nuance: `OS-25`, `OS-32`, `OS-34`, and `WK-05` because these directly shape whether a session keeps moving without outside chat context.
3. Participant rule watchlist: `API-07` is currently good and #163-aligned; preserve that shape when fixing neighboring validation paths.
4. Configuration/setup clarity: `API-01`, `API-17`, `API-19`, and `API-20` should name exact env vars or dependencies in-band.

No code paths were changed during this audit.
